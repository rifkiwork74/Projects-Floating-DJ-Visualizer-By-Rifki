# V3.0.18.3 — Single Low-Frequency Meter Recovery

## Regression identified

V3.0.18.2 introduced a full-frame peak normalization step for PCM. That level control is retained for the Horizontal 64-band path because it was part of the vocal/mid improvement, but it must not be allowed to control a narrow Single/DJ range. A large peak elsewhere in the spectrum can otherwise change the gain applied to the selected low band from frame to frame.

A second issue was in the render path: the service calculated a selected-range value at `levels[64]`, but `FloatingSceneSpectrumView` sampled the 64-band Horizontal bank (`levels[0..63]`) for each profile's Single/DJ range. The separately calculated selected-range value was therefore not the actual input to the meter.

## Changes

- Append a 256-band logarithmic Single/DJ bank to each spectrum frame while keeping the original 64-band Horizontal bank and global meter slot intact.
- The bank is calculated separately for Android `Visualizer(0)` and stereo PCM playback capture from their existing FFT magnitude data.
- PCM Single/DJ levels use raw left/right FFT magnitudes combined by RMS after channel FFT and a separately calibrated, bounded 30.0 single-range scale. They do not inherit full-frame peak normalization from unrelated frequencies. Horizontal PCM levels retain the existing V3.0.18.2 calibration.
- Store the actual FFT bin width in the frame. If a requested Single range is narrower than one bin, widen the effective measurement symmetrically to one bin width. This is a measurement limit, not a change to the user's displayed Hz range.
- Use the same bank, per-profile range aggregation, and attack behavior for Floating Overlay and the in-app Live Display.
- Apply a faster time-based attack only to Single/DJ meters; preserve the release curve and Horizontal response smoothing.

## Expected effect

- Recover low-frequency kick energy in narrow Single/DJ ranges such as 55–62 Hz.
- Reduce low-band level pumping caused by unrelated mid/high peaks in PCM capture.
- Make the Single meter's attack less held-back without speeding up Horizontal bars.
- Keep M.Projection OFF on the Android Visualizer output-mix route and M.Projection ON on user-authorized AudioPlaybackCapture. These sources remain subject to their respective Android/device capability limits.

## Limits and verification

A 55–62 Hz interval is only 7 Hz wide. If the active capture FFT has a wider bin spacing (for example, an AOSP Visualizer capture capped at 1024 samples), the analyzer cannot physically resolve that interval exactly. The new logic uses the real bin width as a minimum measurement bandwidth instead of presenting interpolated sub-bin values as independent resolution.

Static source checks and synthetic signal tests do not replace a CodeAssist `assembleDebug` build or playback tests on the target device. Test the same passage and volume with M.Projection OFF and ON, and record the negotiated capture mode, sample rate, applied FFT size, and bin width.
