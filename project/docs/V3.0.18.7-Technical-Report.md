# V3.0.18.7 Technical Report

## Scope

Baseline: V3.0.18.6 (versionCode 101)  
Output: V3.0.18.7 (versionCode 102)

This update is limited to Equalizer preset state/UI behavior, Visualizer restart-mode restoration, and Floating Profile layer linking. The verified V3.0.18.5 audio engine baseline is intentionally unchanged.

## 1. Equalizer confirmation contrast

`EqualizerActivity.showEqConfirmDialog` now evaluates the minimum contrast of the confirmation button text against the two actual accent-gradient stops (`lighten(themeAccent, 0.12)` and `darken(themeAccent, 0.12)`). It compares the darker text candidate with white and selects the one with the stronger minimum contrast. This handles light gold/custom accent colors without forcing white text onto a light button.

## 2. Dedicated Current State record

`persistCurrentState()` writes a defensive `EqProfile.copy` using the dedicated `currentStateEntryId`, localized Current State name, and cloned band arrays. Named presets remain separate repository items. On first launch, the fallback active profile is created directly with the dedicated Current State ID and persisted after capability refresh, rather than treating the initial state as a built-in Flat preset.

`applyProfile()` no longer persists the applied preset as Current State. Therefore selecting a library preset cannot overwrite the last working snapshot. The preset selector uses the confirmation flow when switching from Current State or edited working values:

- Yes captures the current live band/effect values, stores them under the dedicated Current State identity, then applies the selected library preset.
- No leaves the current working profile active and marks the dropdown as Current State.

Actual fader/effect changes continue to call `persistCurrentState`; applying a named preset alone does not. Import-to-Current-State also uses the dedicated ID rather than borrowing the currently selected library preset ID.

## 3. Save To visual parity

Save To target rows use the preset dropdown's section label pattern, 60dp row height, rounded themed surface, single-line autosized title, concise subtitle, and chevron. Its target source remains filtered to user-created presets with exactly the active band count; built-in entries are excluded.

## 4. Stop / Start requested-mode restoration

The explicit Stop flow records `restore_mprojection_on_start` and `restore_floating_overlay_on_start` before clearing ephemeral runtime values. On the next Start, `restoreLastVisualizerModesAfterStart()` reads those requested flags. Floating restores only when its Android overlay permission is available. M.Projection restoration always invokes a new Android MediaProjection consent request; the previous runtime token is not reused. The EQ service is not stopped by Visualizer Stop.

## 5. Position + Visibility link groups

`FloatingLayerProfile` has nullable `positionVisibilityLinkId`, read/written in the Floating Profile JSON library and emitted in the Floating profile service payload. Since scenes snapshot the full profile library JSON, the link membership is retained in saved scenes too.

The layer-row Linked button operates relative to `selectedFloatingProfileId` as the master. A non-selected row toggles membership in the selected layer's group. Tapping the selected master's own Linked button offers to unlink the entire group. New layers explicitly start with no group ID.

Only these operations use the group:

- **X/Y position:** the selected member's effective post-clamp movement delta is applied to the other group members, with each member's own coordinates retained as the offset. The same propagation is applied after a dynamic overlay drag finishes.
- **Visibility:** hide/show from one member sets the same visibility state on all members.

Rename and Delete remain individual. Deleting or unlinking a member removes a remaining singleton group ID. Canceling the Position dialog restores the original position snapshots for all linked members.
