# V3.0.18.6 Technical Report

## Scope and baseline

- Project: Floating DJ Visualizer
- Baseline: V3.0.18.5 / version code 100
- Release: V3.0.18.6 / version code 101
- Main source files reviewed/modified: `EqualizerActivity.kt`, `MainActivity.kt`, `FloatingVisualizerService.kt`
- Audio processing implementation is preserved from V3.0.18.5.

## 1. Equalizer UI and preset safety

### Mixer-style effect thumbs

`applyEffectMixerThumb()` applies a 34 × 18 dp oval `GradientDrawable` thumb to the horizontal Bass Boost and Virtualizer controls. The existing band mixer faders are untouched.

### Save To target filtering

`saveToPreset()` now filters out every profile recognized by `isBuiltInPreset()` and only offers custom profiles with the current native band count. This prevents built-in 5/10-band curves from appearing as overwrite targets and avoids changing a saved profile's band topology during Save To.

The existing built-in predicate covers the `builtin_` ID namespace and the special `flat` entry. Rename and delete paths explicitly reject built-in profiles as a second safety check.

Selecting a custom target opens a themed confirmation dialog describing the exact preset being overwritten. Delete also uses a themed confirmation. The preset chooser uses a scrollable list with the app's panel, row, typography, and accent styling.

### Band reset confirmation

Each band reset reads the current engine value in millibels and presents the current value as dB, the target value as dB, and the fact that only the selected frequency is affected. The engine write occurs only after Yes. The fader, value label, working-state profile, and persisted current state are updated only after a successful engine read-back.

### Responsive controls and themed name prompt

The four preset action buttons are constrained to one line, ellipsize, and auto-size within a 7–10 sp range. The custom Save As/Rename dialog uses the app's themed panel and controls, bounded width (`min(460 dp, screen width - 32 dp)`), and a single-line EditText to avoid the previous stock dialog presentation and reduce clipping on narrow displays.

## 2. Notification theme text

`notificationThemeTextColor()` now treats both `GLASS` and `CUSTOM` as system-appearance-aware for notification content only:

- System Light: `#17243A`
- System Dark: `Color.WHITE`

`notificationStudioIsLight()` also treats GLASS/CUSTOM as system-aware so the secondary text and notification control styling use a consistent Light/Dark palette. Explicit LIGHT and DARK modes remain explicit and continue to use their configured color preferences.

## 3. Stop behavior and independent EQ lifecycle

### Confirmation

The MainActivity Stop control calls `requestStopVisualizerConfirmation()`, implemented with the existing `showGlassConfirmDialog()` component. The message explicitly states that Visualizer audio analysis, overlay, and the Visualizer host notification will stop, while the independent EQ engine and its notification remain active.

The Visualizer notification's Stop row now launches the same confirmation through `EXTRA_CONFIRM_STOP_VISUALIZER`.

### Service shutdown

After confirmation, `stopFloating()` sends `FloatingVisualizerService.ACTION_STOP`. The service action:

1. releases the Visualizer and MediaProjection/AudioRecord resources through `stopEngineResources()`;
2. removes the floating overlay;
3. clears only Visualizer/overlay/backup runtime flags;
4. removes the Visualizer foreground notification and stops its service.

The action deliberately does not call `stopService()` on `EqEngineService` and does not modify the EQ service's enabled preference. This preserves the independent EQ notification and service lifecycle.

The Activity sends a normal service command while foregrounded, avoiding an unnecessary `startForegroundService()` launch solely for a stop command.

## 4. Portable General Settings import

The exporter continues to produce the existing `FloatingDJVisualizer` JSON envelope and settings object. The import parser now:

- accepts `settings`, `preferences`, or `prefs` as the settings object;
- accepts UTF-8 BOM and a maximum 4 MB file;
- respects known allowlisted/local SharedPreferences types;
- also accepts JSON scalar values for keys not yet initialized on the receiving device, instead of dropping every unknown key;
- skips nested values except the separately validated floating profiles/scenes/EQ bundle;
- explicitly excludes service-active, overlay-active, backup-capture, MediaProjection/session, and permission-grant values;
- logs the exact validation exception under `FloatingDJBackup` and includes the failure detail in the user toast.

The commit path keeps Visualizer, overlay, M.Projection and EQ runtime sessions off; EQ presets/current-state may be imported as data, but a live EQ session is not migrated. If the source backup indicated Floating Overlay was enabled, the existing post-import confirmation is shown so the target device can choose whether to activate its own overlay after checking its local permission.

### Compatibility note

This improves compatibility for current and future scalar preference keys and makes the import error diagnosable. The user's original failed JSON backup was not attached in this task, so its exact historical failure cause cannot be conclusively identified. A real export/import between two Android devices is still required to confirm the specific file/provider/device combination.

## 6. Validation limitations

Static source review and archive/resource validation are performed before packaging. This environment does not expose the CodeAssist Android SDK/Gradle build, so no APK compile result is claimed. Device tests are still needed for:

- 360 dpi/default text scale and 500 dpi layouts;
- Bass Boost/Virtualizer thumb appearance;
- Save To list ordering and built-in protection;
- every themed dialog in LIGHT, DARK, GLASS, and CUSTOM;
- Visualizer Stop with EQ Engine already running and its notification visible;
- General Settings export from device A and import to device B with different runtime permission states.
