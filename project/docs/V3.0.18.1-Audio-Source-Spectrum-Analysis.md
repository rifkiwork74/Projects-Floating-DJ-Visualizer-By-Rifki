# V3.0.18.1 — Audio Source & Spectrum Analysis

## What the two sources actually do

### MediaProjection (ON)

The service requests Android playback capture for `USAGE_UNKNOWN`, `USAGE_MEDIA`, and `USAGE_GAME`, then reads PCM16 through `AudioRecord` at 44.1 kHz. Capture still depends on the source app's usage and capture policy; an app can disallow third-party playback capture. This is not an unrestricted system mixer and does not expose BPM metadata.

The previous implementation requested `CHANNEL_IN_MONO`. It therefore allowed the capture path to combine left/right material before FFT. Stereo differences and anti-phase content can be reduced by this downmix. V3.0.18.1 prefers `CHANNEL_IN_STEREO`, computes left and right FFTs separately, then combines magnitudes by RMS energy. If stereo initialization fails, it falls back to mono and logs that limitation.

### Android Visualizer (OFF)

The service creates `Visualizer(0)`, which is attached to the output mix. Its capture size must be a power of two inside `Visualizer.getCaptureSizeRange()`. The requested UI FFT value can therefore be reduced to a device-supported capture size. The applied size and callback rate are now logged. The callback rate is selected from `Visualizer.getMaxCaptureRate()`; Hop Size does not exist on this API path.

## FFT and Hop at 44.1 kHz

| Setting | Value | Meaning |
|---|---:|---|
| FFT | 4096 samples | 92.88 ms analysis window; 10.77 Hz/bin |
| Hop | 512 samples | 11.61 ms update interval; 87.5% overlap |
| Hop | 256 samples | 5.80 ms update interval; 93.75% overlap |

The hop interval is not the FFT window duration. A smaller hop refreshes overlapping analysis windows more often, but it does not turn a 92.88 ms window into a 5.80 ms window. The screen animation still renders on display frames and may coalesce older audio updates.

## Why the same Response percentage can feel different

Response controls the time-based attack/release smoothing of rendered bars. It does not set the capture callback rate, FFT size, or Hop. At the same Response value, the animation smoothing curve is the same, but the two sources can supply new target spectrum frames at different intervals and resolutions. A 5.80 ms PCM hop can refresh targets much more often than a Visualizer implementation whose callback is limited by the device.

## Spectrum mapping changes

- Horizontal bands remain a fixed logarithmic 20 Hz–20 kHz bank; they do not inherit the Single/DJ bass-range selection.
- Single/DJ range measurement is separate and now uses frequency interpolation when the selected range is narrower than one FFT bin. This is important when the device Visualizer applies a smaller capture size than requested.
- Horizontal band energy now scans all FFT-bin centres inside each logarithmic band and combines RMS energy with peak retention. The previous fixed five-point sampling could miss a narrow vocal or harmonic peak between probe frequencies.

## What this update does not claim

- MediaProjection is not a BPM detector. BPM/beat estimation requires a separate onset/tempo analysis stage and is not inferred from the current FFT bars.
- MediaProjection does not capture every app. Source-app audio usage and capture policy restrictions still apply.
- A larger requested Visualizer FFT does not guarantee the device will apply that size; check the runtime log for the applied size.
- The two APIs cannot be guaranteed to produce identical waveforms because their capture points, scaling, device implementation, and update schedules differ. The goal is more consistent spectrum measurement and better stereo preservation, not to fake equal callback timing.

## Device test plan

1. Use the same player, track, volume, output route, bar count, and Response value for both capture sources.
2. Run `Visualizer OFF` with FFT 4096 and Hop 256/512. Record the log's **applied capture size** and callback interval. Hop should be reported as N/A.
3. Run `MediaProjection ON` with FFT 4096, first Hop 512 then Hop 256. Confirm the log reports `channels=2` where stereo capture is supported.
4. Compare centered bass, mono vocals, wide/chorused vocals, cymbals, and high-frequency percussion.
5. Set Single/DJ range to 55–62 Hz and verify it changes only the Single/DJ indicator, not Horizontal's 20 Hz–20 kHz bars.
6. If the device falls back to mono, record that status; compare the same stereo-heavy section to identify phase-cancellation sensitivity.
7. Capture Logcat with tag `FloatingDJ.Audio` for FFT size, bin resolution, window duration, hop interval, channel count, and callback interval.
