# Floating DJ Visualizer V3.0.18.5 — Release Notes

**Stereo Capture Session Stability & Direct-Level Recovery**  
**Version Code:** 100  
**Baseline:** V3.0.18.4 / Version Code 99

## What's fixed

- Changing FFT Size or Hop Size no longer requires destroying and rebuilding the active MediaProjection `AudioRecord`.
- The current MediaProjection session is retained while the PCM analysis worker is restarted with the new settings.
- Worker generation IDs prevent an older blocked reader from reactivating or reporting a false stream failure after a settings change.
- Settings-only errors use a separate warning state; they no longer automatically switch to Android Visualizer(0) or turn the M.Projection switch OFF.

## Spectrum behavior

- Restore the fixed PCM Horizontal calibration to `9.0`, matching the V3.0.18/V3.0.18.1 reference curve.
- Keep stereo L/R FFT processing and post-FFT RMS magnitude combination from V3.0.18.1.
- Keep the V3.0.18.3 Single/DJ 256-band bank and its independent range calibration (`30.0`).
- Do not apply frame-peak or content-dependent global normalization.
- Preserve actual capture sample-rate mapping.

## Compatibility and limitations

- No new permissions or microphone capture route.
- M.Projection remains a user-approved Android playback-capture route.
- Android Visualizer remains the M.Projection-OFF route; Hop Size is not available on that route.
- Android assembleDebug has not been run here; verify compilation and real playback on the target device.

## Test focus

1. Confirm M.Projection stays ON while changing FFT and Hop Size.
2. Compare M.Projection OFF vs ON using the same song and volume.
3. Recheck vocals, low-frequency beat response, and stereo material.
4. Confirm Live Display and Floating Overlay remain synchronized.
