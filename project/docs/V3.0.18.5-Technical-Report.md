# Floating DJ Visualizer V3.0.18.5 — Technical Report

## Scope

Baseline: V3.0.18.4 (versionCode 99).  
Comparison references supplied by the user: V3.0.18 (mono PCM capture) and V3.0.18.1 (stereo PCM capture).  
Target: preserve V3.0.18's direct, punchy fixed-level behavior while keeping V3.0.18.1's stereo-aware analysis and avoiding the source-switch regression when FFT/Hop values change.

## Findings from source comparison

### 1. V3.0.18 vs V3.0.18.1

- V3.0.18 creates a mono `AudioRecord` and runs one FFT over that mono stream.
- V3.0.18.1 prefers stereo playback capture, performs an FFT separately for Left and Right, and combines per-bin magnitudes using RMS energy: `sqrt((L² + R²) / 2)`.
- The stereo approach avoids cancelling anti-phase vocal/chorus material through a pre-FFT L/R waveform average. This is retained.
- The V3.0.18/V3.0.18.1 Horizontal PCM curve uses a fixed factor of 9.0 before the square-root display curve.

### 2. V3.0.18.2–V3.0.18.4

- V3.0.18.2 introduced frame-peak normalization across the PCM spectrum. That makes the gain applied to one band depend on the peak level elsewhere in the same frame.
- V3.0.18.3 separated out the higher-resolution Single/DJ bank, which is retained because the user's device tests confirmed the 55–62 Hz and 850–1200 Hz ranges work well.
- V3.0.18.4 removed the global PCM frame normalization, but retained a lower Horizontal PCM fixed scale of 5.08. This update restores the V3.0.18.1 fixed Horizontal scale of 9.0 while leaving the Single/DJ 256-band scale at 30.0.

## M.Projection FFT/Hop switch-off path

In V3.0.18.4, `ACTION_UPDATE` called `restartProjectionCaptureForAnalysisSettings()`. That method:
1. stopped and released the current `AudioRecord`;
2. kept the current `MediaProjection` object;
3. attempted to build and start a replacement `AudioRecord`;
4. returned failure if the replacement could not initialize.

The caller then stopped all Projection resources and switched to the primary Visualizer, sending `BACKUP_ERROR`. `MainActivity` handled that status by setting `backup_capture=false` and turning the switch OFF. There was also a race risk: the previous PCM worker was joined for only 500 ms while the shared `backupRunning` flag could later be set TRUE by a new worker.

## V3.0.18.5 implementation

### 1. Preserve the capture session

FFT/Hop changes now stop the current PCM analysis worker, wait for it to finish, and restart the same initialized `AudioRecord`. The `MediaProjection` object and user consent session are retained. The recorder's initial buffer is reserved for the maximum supported 4096-point FFT/2048-frame Hop, so future analysis-window changes do not need a new recorder.

### 2. Protect worker lifecycle

Every PCM reader receives a generation number. When a reader is invalidated, the generation changes. Old workers check both their running flag and generation before reading, publishing levels, or reporting stream failures. This prevents a stale worker from waking up under a later worker's shared running flag and prevents settings updates from causing an old worker to trigger a source fallback.

### 3. Keep route status explicit

A settings-only reconfiguration failure now produces `BACKUP_RECONFIG_ERROR`, not `BACKUP_ERROR`. The UI keeps the M.Projection selection enabled and shows a warning state rather than silently selecting the primary Visualizer route. A true playback-capture stream failure still follows the existing `BACKUP_ERROR` handling.

### 4. Fixed calibration and stereo path

- PCM Horizontal fixed scale: 9.0 (V3.0.18/V3.0.18.1 reference).
- PCM Single/DJ range scale: 30.0 (retained from V3.0.18.3/18.4).
- Stereo: independent L/R FFT followed by RMS magnitude combine per bin.
- No frame-peak, whole-spectrum, or content-dependent gain normalization.
- Actual negotiated `AudioRecord.sampleRate` remains the basis for Hz mapping.
- Single/DJ's independent 256-band frequency bank and per-profile range calculation remain unchanged.

## Important API note

The two routes are not the same capture API. M.Projection ON reads authorized PCM playback capture; M.Projection OFF reads Android `Visualizer(0)` output-mix FFT data. The update uses the same frequency mapping and fixed, non-dynamic calibration strategy where possible, but bit-identical magnitudes cannot be guaranteed across those distinct Android routes and device implementations.
